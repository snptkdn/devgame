# ビジネス人生シミュレーション 設計・仕様メモ

## 1. コンセプト

成功者の人生をリアルに追随するブラウザゲーム。
1ターン=1年で、毎年の「時間の割り振り」を決定し、パラメタを積み上げていく。

イベントテキストによる分岐は基本的に持たない。すべての出来事は「パラメタの変動」と「割り振り枠の圧迫・解放」として表現する。内部的にフラグやイベントを持つのは構わないが、プレイヤーに見える形では「行動を積んでパラメタが伸びる」「生活費が圧迫してくる」といった数字とリソースのやりくりのみで一本化する。

今回のMVP（Minimum Viable Product）では、まずは「1世代（子供への引き継ぎなし）」「ITサラリーマンのみ」で基本サイクルが回ることを目標とする。

## 2. 100%割り振り制（行動システム）

1ターン（1年）につき、**100%のリソース（時間・労力）を各行動に自由に割り振る**システムを採用する。
初期の行動選択肢は以下の4つ：
- **仕事**: 資金を稼ぐ。技術パラメタや地頭の良さによって成果（案件の成功）が変わる。
- **休養**: 健康パラメタの維持・回復。
- **勉強**: 技術パラメタを伸ばす。
- **遊ぶ**: 人脈パラメタを伸ばす、あるいはストレス解消。

**「人生の重さ」の表現**
パーセンテージの強制固定や上限設定によって人生の枷を表現する。
- 例：起業すると「仕事」に最低60%の割り振りが強制される。
- 例：健康が著しく低下すると、合計で80%までしか割り振れなくなる（残りの20%は無駄になる）。
※MVP時点ではシンプルな割り振りを実装する。

## 3. パラメタ設計

パラメタは基本的に「資金」以外は**非公開（マスクデータ）**とする。「伸びたこと」自体はわかるが、絶対値は見えない。

### 必須パラメタ
1. **資金 (Visible)**: 現在の所持金。唯一明示的に見える数値。
2. **技術 (Hidden)**: 案件の成功率や、より上位の案件を受けられるかに影響する。
3. **健康 (Hidden)**: 低下すると行動枠の上限が削られたり、死亡確率に悪影響を与える。
4. **人脈 (Hidden)**: 案件の幅や質、将来的な転職時の有利さに影響する。
5. **地頭の良さ (Hidden)**: 開始時に決定される先天的な才能。正規分布（標準偏差）を用いてランダム生成される。勉強による技術の伸びやすさや、仕事の成果（成功率）に強力なバフとして働く。成長はしない。

## 4. 生活水準と固定費の罠

生活水準（食費・住居・交際費など）は、**収入に応じて自動的に上昇する**。
稼げば稼ぐほど生活水準が勝手に追随し、毎年の固定費が跳ね上がっていく。

**下げるためのコスト**
生活水準を下げるには明示的に設定を絞る必要があるが、絞るとペナルティが発生する。
- 食費を絞る → 金は貯まるが「健康」が下がる。
- 交際費を絞る → 「人脈」が下がる。
この生活水準の罠により、収入が落ちた時（起業時など）に固定費に苦しめられる葛藤を生み出す。

## 5. 年齢進行と死亡判定（終了条件）

MVPにおける1回のプレイは、**キャラクターが死亡した時点で終了（ゲームオーバー）**となる。
固定のターン制限（60ターンで引退など）は設けず、現実の統計データを参考にした**年齢ベースの死亡確率**を毎ターン判定する。
- 20代など若年層でもごく僅かながら死亡確率は存在する（事故や病気など）。
- 高齢になるにつれて死亡確率が指数関数的に上昇していく。
- 「健康」パラメタが低い状態が続くと、この死亡確率がブーストされる。

## 6. 技術スタック・アーキテクチャ

- **フロントエンド**: React + Vite (TypeScript)
- **配信**: GitHub Pagesを想定（静的サイトとしてビルド結果をホスティング）
- **状態管理**: 当面はReactのContextやStateで管理。バックエンドは不要。
- **設計思想**: コアのゲームエンジン（パラメタ計算、ターン進行、死亡判定など）と、UIコンポーネントは分離する。将来的には職業ごとのパラメータや案件ロジックをJSON化し、データ駆動でバランス調整できるようにする。
